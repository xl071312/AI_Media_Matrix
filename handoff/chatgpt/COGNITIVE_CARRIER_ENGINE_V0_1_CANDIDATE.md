# Guanyu Cognitive Carrier Engine v0.1 — CANDIDATE

Date: 2026-09-13
Owner: ChatGPT
Status: CANDIDATE
Purpose: make complex ideas feel easy by carrying them through one familiar object, scene or calculation.

## Key finding

The corpus suggests a distinction we had not made explicit enough:

**A good example is not decoration. A good example can carry the whole argument.**

The strongest explanatory pieces often do not jump from example to example every few sentences. They select one familiar carrier and keep reusing it while the reasoning becomes deeper.

## Primary evidence

### 7591984049339256177 — one bottle of water
The speaker begins with a two-RMB bottle of water and repeatedly changes only the selling place, buyer, packaging, urgency and service mode. The same object is then used to explain pricing, buyer urgency, identity, product/service/solution differences and income ceiling.

The listener does not have to learn a new example each time. The object stays fixed while the variable changes.

### 7672991243072616697 — one million RMB split three ways
The speaker holds the goal fixed at one million RMB and changes only:
- number of buyers
- money earned per buyer

This lets the listener compare paths without learning business vocabulary first.

### 7647446230122356665 — one small fruit-store test
The argument about entrepreneurship is carried by a single practical test: spend a small amount, offer samples, ask whether people want to add WeChat, then decide from the response. `validation` becomes a thing the viewer can imagine doing tomorrow.

### 7682791681556548883 — human service vs mass production
The speaker explains AI boundaries through familiar services: cooking help, installing lights, caregiving, plumbing. The repeated variable is whether the task requires handling a changing physical situation.

## Carrier principle

For a difficult topic, choose:

`one familiar thing + one changing variable`

Examples:
- water + selling place
- one-million goal + buyer count
- small shop + test cost
- salary + employer count
- one task + how clear the steps are
- one customer problem + who can approve money

The listener should not need to reload the mental scene at every cognitive node.

## When one carrier is better than many examples

Prefer one carrier when:
- the video explains a mechanism rather than a list of facts;
- 3–5 cognitive gains can be shown by changing one variable;
- the topic is abstract;
- the audience may not know the domain;
- the goal is a reusable mental model.

Multiple examples are still useful for proving transfer, but they should usually come after the main mechanism is understood.

## The one-variable-at-a-time rule

Bad explanation:
`AI affects programmers, then talk about teachers, then shops, then parents, then factory workers, then return to software.`

The listener repeatedly pays context-switch cost.

Better:
Hold one job/task constant and change one property:
1. steps are fully specified;
2. steps are partly specified;
3. outcome is specified but method is not;
4. physical scene changes every time;
5. customer/people judgment matters.

Now the listener can see exactly what changes the replacement risk.

## Carrier selection test

A carrier is good if all are true:
1. Chinese ordinary viewers recognize it immediately.
2. It can be stated in one sentence.
3. It supports at least 2–3 reasoning moves.
4. It has numbers/actions or visible choices.
5. It does not require specialist knowledge.
6. It is not emotionally unrelated to the topic.

If a carrier needs more than ~10 seconds of background, reject it for the opening mechanism.

## Carrier types

### C1 Money arithmetic
Use when the mechanism depends on price, revenue, cost, scale, unit economics or risk.

Pattern:
`same goal -> different number of people / different price -> compare feasibility`

### C2 Everyday object
Use one object whose price/use changes with context.

Pattern:
`same object -> change place/person/time/packaging -> observe price/value change`

### C3 One small business
Use one shop/product/customer throughout.

Pattern:
`idea -> test -> customer response -> spend more or stop -> repeat/scale`

### C4 One workplace task
Use one assignment from boss to employee.

Pattern:
`instructions very detailed -> partly detailed -> only outcome specified -> compare who/what can do it`

### C5 One service scene
Use haircut, repair, caregiving, delivery, installation or other familiar service.

Pattern:
`same result -> different process/interaction -> different willingness to pay`

### C6 One buyer
Follow one buyer from pain -> search -> trust -> first purchase -> repeat.

Useful for monetization/transaction explanations.

## News adaptation rule

Do not let a news event become the carrier unless ordinary viewers already understand it.

For news videos:
1. choose an ordinary-life carrier first;
2. explain the mechanism through that carrier;
3. use the news as proof that the same mechanism appears at larger scale.

If the viewer must learn a foreign company, policy institution and industry background before seeing the mechanism, topic entry is wrong.

## Anti-AI rule: no analogy parade

AI-written scripts often produce:
`this is like X, also like Y, and in fact like Z.`

Reject analogy stacking.

Default:
- one main carrier;
- one secondary transfer example only after mechanism clarity;
- one final real-world/news anchor.

## Suggested 4–5 minute carrier spine

0–15s: show carrier/result/conflict.
15–45s: ask one concrete question about it.
45–120s: change variable #1 and #2.
120–200s: change variable #3 / show edge case.
200–250s: connect carrier to viewer's actual decision.
250–285s: compress into a reusable rule.
Final: one transfer example proving the rule is not only about the carrier.

## Plain-language payoff

The desired experience is:

`我一直听的是水/工资/一个老板/一家小店 -> 但最后我突然懂了一个更大的商业或职场问题。`

That is preferable to:

`我一直听的是框架、变量、机制、权重 -> 最后还要自己想它跟我有什么关系。`
